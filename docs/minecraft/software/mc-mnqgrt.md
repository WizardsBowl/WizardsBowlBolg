## 目的&效果

在[Java版1.21.9](https://zh.minecraft.wiki/w/Java%E7%89%881.21.9)中，MC加入了[玩家模型（Mannequin）](https://zh.minecraft.wiki/w/%E7%8E%A9%E5%AE%B6%E6%A8%A1%E5%9E%8B)这样一种实体，只能由命令生成，拥有玩家的外观（模型、皮肤、披风）和类似盔甲架的功能（当然，你只能以命令的方式给它穿戴装备）。而每一个玩家模型所使用的皮肤数据，都取决于它的[profile组件](https://zh.minecraft.wiki/w/%E6%95%B0%E6%8D%AE%E7%BB%84%E4%BB%B6#profile)。

本程序的目的，就是简化生成玩家模型的流程，通过输入必要的信息，就可以生成能在游戏内直接使用的指令，以及可选的资源包。生成的玩家模型带有相应的NBT数据（包含profile组件数据），因此会具有相应的皮肤与披风。

在程序页面上半部分输入必要的信息，点击`生成`按钮，等待一会，就会在页面下半部分输出生成的指令。之后再把这些指令复制到游戏中执行就好。

5. 在页面最下方`材质数据`一栏内查找`"SKIN" > "url"`（皮肤）和`"CAPE" > "url"`（披风，可能不存在），其对应的数据值就是你的皮肤/披风文件在官方服务器上的URL。

在此基础上，你可以在官方服务器上传一个新的皮肤文件并取得对应URL：

1. 备份你当前的皮肤文件。
2. 在官网或官启中更换你的皮肤为一个新的皮肤。
3. 按照前述方法取得你的新皮肤的URL并保存。
4. 在官网或官启中换回你原先的皮肤（如果你想的话）。
5. 你在第3步中获取的URL仍然有效并指向那个“新皮肤”。

:::

### 生成指令

生成的指令一共有三条：

1. 生成玩家模型指令：原地生成玩家模型实体。
2. 给予玩家模型指令：给予最近的玩家一个刷怪蛋，使用后生成玩家模型。
3. 给予玩家头颅指令：给予最近的玩家一个玩家头颅。

::: warning
聊天框内输入指令有字数限制，若字数过长则会被截断。因此当指令过长时，应使用命令方块执行指令。
:::

### 生成资源包

如果你选择了资源包模式，则会在指令生成之后自动下载一同生成的资源包（保存至你浏览器的下载文件夹）。

资源包内含有你选择的皮肤和披风文件，此外还会将生成的三条指令一并打包进`commands.txt`文件中。

::: warning
使用资源包模式生成的指令，必须在游戏启用对应资源包的情况下使用。
:::

## 联网需求

根据你选择的`档案来源`模式，在使用时的不同阶段内对联网情况有不同要求。

| 档案来源模式 | 生成指令时需联网 | 游戏内使用时需联网 | 多人联机时他人可见性 |
| :---: | :---: | :---: | :---: |
| 实时更新 | 是 | 是 | 是 |
| 预先存储URL | 是 | 是 | 是 |
| 自定义URL | 否 | 是 | 是 |
| 资源包 | 否 | 否 | 仅对启用资源包的人可见 |

## 模式差异

四种`档案来源`模式之间，除了上述的对输入信息和联网情况的需求有差异之外，其实际使用效果也存在一定差异：

### 实时更新模式

游戏会在加载纹理时自动下载并使用对应玩家的皮肤。如果该玩家在官网上更换了皮肤，则游戏内玩家模型的皮肤也会同步更新。模型种类（粗/细手臂）也会与该玩家在官网上的实时设置保持一致。由于本程序在指令内实际存储的是玩家id而不是玩家名称，该玩家改名并不会影响到游戏解析其皮肤数据。

### 预先存储URL模式

本程序在生成指令时自动获取对应玩家的皮肤文件的URL，并将此URL存储在指令附带的NBT数据中。当游戏加载纹理时，会直接依据这个URL下载皮肤文件。由于URL是与皮肤文件永久性对应的而并不与玩家永久对应，即使该玩家之后再更换皮肤，也不会影响到游戏内已存在的玩家模型的皮肤。此外，模型种类信息也是在生成指令时就确定下来并固定不变的（自动与生成指令时该玩家的设置保持一致）。

### 自定义URL模式

与`预先存储URL`模式基本相同，只不过存储在指令附带NBT中的URL是由你手动输入的自定义URL。此外，模型种类信息也需要你在生成指令时给出。

### 资源包模式

游戏不会尝试下载皮肤文件，而是直接使用资源包内存储的皮肤文件。模型种类与你在生成指令时的设置一致。

## 基本原理

MC解析玩家模型的皮肤数据基本上可以分为以下几步：

1. 通过玩家名称查询玩家数字id（需要联网）。
2. 通过玩家数字id查询玩家皮肤/披风URL以及模型种类（需要联网）。
3. 通过URL下载皮肤/披风文件（需要联网）。
4. 将下载好的材质文件应用到玩家模型上（无需联网）。

本程序的不同`档案来源`模式，就相当于替代游戏提前完成某一步的操作：

- 实时更新模式：第1步。
- 预先存储/自定义URL模式：第2步。
- 资源包模式：第3步。

当任一步骤被替代完成之后，其之前的所有步骤将不会被执行。

## 高级选项

仅当`启用高级选项`被勾选时，这些选项才会生效。

### 资源包格式版本

生成的资源包的格式版本，详见[Wiki相关页面](https://zh.minecraft.wiki/w/%E8%B5%84%E6%BA%90%E5%8C%85#%E8%B5%84%E6%BA%90%E5%8C%85%E6%A0%BC%E5%BC%8F%E7%89%88%E6%9C%AC)。目前只能指定主要版本号。

如果游戏提示资源包版本不适用，可以尝试更改此选项。注意，目前此方法治标不治本，并不会实际上影响资源包的有效内容。

### 资源包图标文件

自定义的资源包图标文件。

### 模型标签文本

对应[其NBT数据](https://zh.minecraft.wiki/w/%E7%8E%A9%E5%AE%B6%E6%A8%A1%E5%9E%8B#%E6%95%B0%E6%8D%AE%E5%80%BC)中的`description`标签。显示在玩家模型名牌下方的标签文本。若留空则不会在生成的NBT中带有此项。

### 隐藏模型标签

NBT中的`hide_description`标签。是否隐藏模型标签文本。

### 模型不可移动

NBT中的`immovable`标签。模型是否不能被移动。

### 模型无敌

NBT中的`Invulnerable`标签。模型是否免疫绝大多数伤害（不包括来自创造模式玩家的伤害，虚空伤害，kill命令等）。

### 模型主手

NBT中的`main_hand`标签。模型的主手，可以为`右手`或`左手`。

### 模型姿势

NBT中的`pose`标签。模型的姿势，可以为`站立`，`潜行`，`游泳`，`滑翔`或`睡觉`。

## 离线使用

由于本程序以PWA（渐进式网页应用程序，Progressive Web App）（[MDN](https://developer.mozilla.org/zh-CN/docs/Web/Progressive_web_apps)，[维基百科](https://zh.wikipedia.org/wiki/%E6%B8%90%E8%BF%9B%E5%BC%8F%E7%BD%91%E7%BB%9C%E5%BA%94%E7%94%A8%E7%A8%8B%E5%BA%8F)）的形式发布，你不仅可以把它当作一个普通网页打开，也可以把它当作一个“普通”的应用程序安装在你的电脑或手机上。安装之后，即使断网，也可以打开并使用部分功能。

### 支持情况

目前基于Chromium的浏览器（如Chrome、Edge）都是支持PWA的（完全支持）。

Safari不完全支持PWA。

Firefox完全不支持PWA。

关于操作系统方面的因素，基本上只要你能安装上支持PWA的浏览器，那就代表可以使用（仅桌面端而言）。!!鸿蒙上的Edge暂时不支持PWA。!!!!其实其他手机系统我也没有试过，我觉得在这方面不用抱太大希望。!!

即使你不能安装也没关系，你仍然可以在线使用PWA应用。

### 检查更新

如果你已经安装了本程序，则在联网的情况下会自动检查更新。当有新版本可用时，会在程序页面右下角显示一个弹窗，提示“New contents available.”。此时点击`Reload`即可更新程序。通常几秒钟内就可以完成更新并自动刷新页面。

### 注意事项

安装PWA应用并不会额外安装一个浏览器。你可以理解为它只是把网页资源下载了一份保存到本地（体积通常非常小）。当你打开快捷方式时，它只是使用你已经安装的浏览器打开了这一份本地的网页资源文件而已。!!然而，仍然可能会占用不少“运行”内存。!!
